# EXPERIMENT_PROTOCOL — P1 동일 경험 시험

## 질문
설명서(효과만)와 고정된 무작위 경험으로부터 도구의 전제조건·효과 모델을 배우면, **새 조건**의 파일 과제에서 경험 검색만 하는 비교군보다 실제 완수율이 높아지는가?

## 조건 (차이점 전부)
| | A 고정 지식 | B 경험 검색 | C 규칙 학습 | D 의결(MAGI형) |
|---|---|---|---|---|
| 설명서 효과 | 사용 | 사용(검색 실패 시) | 사용(규칙·검색 실패 시) | 구성원별로 C와 동일 |
| 경험 로그 | 없음 | 동일 로그 | 동일 로그 | 동일 로그를 3등분해 구성원 3명이 나눠 가짐(총량 동일) |
| 예측 방식 | 설명서 효과, 항상 성공 가정 | 상황 서명(들어올린 리터럴 전체)이 **정확히** 같은 경험의 결과를 재사용; 다수결 | 도구별 유도 규칙(전제조건 = 성공 공통 리터럴에서 실패를 배제하는 데 불필요한 것 제거; 효과 = 성공 합의) 우선, 없으면 B와 동일 | 구성원 3명의 성공/실패 예측 다수결; 효과는 가장 근거 있는 동의 구성원(learned > retrieved > documented) |
| 온라인 갱신 | 없음 | 없음(frozen) | 없음(frozen) | 없음(frozen) |
| planner·예산·목표·관측·권한 | 동일 | 동일 | 동일 | 동일 (예측 호출은 3배) |
| ORACLE(진단) | 진실 모델로 계획. planner와 과제가 풀 수 있는지 확인용. 학습 성과와 섞지 않음 | | | |

D는 사용자의 "세 자아가 의결" 가설을 **비교군으로** 넣은 것이다. 아키텍처 채택이 아니라 C 대비 이득 여부를 같은 예산에서 보는 2차 질문이며, 1차 판정(C−B)에 영향을 주지 않는다. 의식·주체성에 관한 주장은 어떤 결과에서도 하지 않는다.

B는 객체 이름을 역할로 추상화하지만 서명에 모든 속성(kind/ext/parent_kind, same_content)을 넣는 **정확 일치** 검색이라 탐색 커버리지에 묶인다. 서명이 없으면 설명서(항상 성공)로 떨어진다. 따라서 C−B는 "규칙 유도의 기여"와 "커버리지 밖 상황의 일반화"를 함께 담는다. 보고서의 `설명서의존`(실행한 행동 중 설명서만으로 예측한 비율) 열로 이를 공개한다.

**D의 투표 규칙(v2):** 구성원 중 근거(학습 규칙 또는 검색 결과)가 있는 구성원만 투표하고, 다수결; 동수는 실패; 아무도 근거가 없으면 A처럼 설명서. v1은 설명서만 가진 구성원도 "성공"에 투표해 사실상 A로 퇴화했다(검토 지적).

## 분할
| 분할 | 용도 | 확장자 | 파일 수 | 목표 디렉터리 깊이 | 객체 이름 |
|---|---|---|---|---|---|
| train | 탐색 경험 수집 | txt, csv | 2–3 | 1 | WORDS_TRAIN |
| dev | 개발·디버그·비용 예비 측정 | txt, csv | 2–3 | 1 | WORDS_TRAIN |
| test | 최종 평가 (1회) | txt, csv, md, log, json | 3–4 | 1–2 | WORDS_TEST (train과 겹치지 않음), 디렉터리 이름도 새것 |

과제 템플릿: backup(복사·원본 보존), sort(확장자별 이동·원본 제거), convert(txt→md 변환·원본 보존; **v2**: 출력이 관측 가능한 모든 파일과 내용이 달라야 하므로 copy/move로는 만족 불가). 모든 과제는 평가기가 진실 모델로 도달 가능성을 확인한다. 도달 불가 과제는 INVALID.

**"새 조건"의 정확한 범위(v2에서 정정):** 탐색 공간(train)에는 `.md` 이름의 대상 경로와 깊이 2 경로(`box/sub/...`)가 이미 있다. test에서 실제로 새로운 것은 객체·디렉터리 이름, 파일 3–4개, 확장자 **log/json**(소스 파일로서), 목표 디렉터리 체인(깊이 2 목표), 필요한 행동 수(최대 10)다. v1 test는 json을 한 번도 생성하지 않았다.

## 예산 (모든 조건 동일)
행동 ≤ 20, **예측 호출 ≤ 400,000/계획 호출(구속 예산, 결정적, 조건 동일)**, 확장 노드 ≤ 600, 깊이 ≤ 12, 시간 180 s는 안전장치(발동 시 정지 이유로 기록) (`eval/generator.py::BUDGET`). v2.1: 10만에서는 ORACLE이 16/20(깊이 2 sort는 확장당 행동 ~750개)이라 학습기 실행 **전에** 40만으로 올렸다(ORACLE 20/20, 예산 정지 0). 탐색 경험: seed당 300 행동(도구 균등 + 서명당 2회까지 우선, 40행동마다 새 작업 공간). test의 가장 긴 과제(깊이 2 sort, 파일 4개)는 10행동이 필요하며 ORACLE이 20과제 전부 예산 내에서 푼다.

## 표본
test 과제 20개(id 0–19 고정, 템플릿 균등) × 경험 seed 5개(1–5) × 4조건 = 400 에피소드 + ORACLE 20(seed 1).
같은 학습 상태에서 나온 과제들은 독립 표본이 아니다. 과제별 paired 차이와 seed별 결과를 공개하고, 신뢰구간은 제시하지 않는다(표본이 작아 불확실).

## 누출 방지
- `agent/`, `core/`, `world/`는 `eval/`를 import하지 않는다(테스트). 학습기는 Goal과 작업 공간 경로만 받는다.
- 평가 seed·템플릿·진실 모델은 `eval/` 안에만 있다. 도구 이름·설명서에 정답 경로 없음.
- 최종 test는 `protocol.json` 동결 후 **한 번** 돈다. 그 뒤 코드를 바꾸면 새 실험 이름으로 기록한다.

## 반드시 보고할 지표
완수율(평가기가 실제 상태로 판정), 부분 충족, keep 위반 수, 행동 수, no-op 수, 보류 수, 예산 초과 수, 환경 오류 수, 차단된 제안 수, 예측 오류 수/예측 수, 조건별 wall·CPU·최대 메모리(tracemalloc)·저장 증가량, 학습 비용(모델 구축 시간) 별도, 템플릿별 완수율, C−B 과제별·seed별 paired 차이.

## 판정 규칙 (값은 protocol.json에 동결. 동결 전엔 EXPLORATORY)
- 완수(primary) = 평가기가 실제 끝 상태로 판정 **그리고** 도중 keep 위반 없음(v2 엄격 정의).
- 라벨이 `pre-registered`가 아니면 판정하지 않는다(`REPLICATION` / `EXPLORATORY`).
- INVALID: 환경 오류 > 0, ORACLE 완수율 < 100 %, 의미 일치 검사 실패(도구×결과 셀당 ≥ 20, 실행별 seed), 유효성 테스트(학습기 성능 테스트 제외) 미실행·실패, 과제 도달 불가.
- VALID_BOUNDED_GAIN: C−B 평균 완수율 ≥ `min_gain_pp` **그리고** seed 중 C ≥ B인 수 ≥ `seeds_ge` **그리고** C의 에피소드 평균 wall ≤ `max_cost_ratio` × B.
- VALID_NO_GAIN: C−B ≤ 0.
- 그 외: VALID_INCONCLUSIVE.
- 2차(판정 무관): D−C에 같은 `min_gain_pp`·`seeds_ge`를 적용해 "의결 이득 있음 / 없음 / 불명"만 기록. B−A, C−A도 참고로 공개.
