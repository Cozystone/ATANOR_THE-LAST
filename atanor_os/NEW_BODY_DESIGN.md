# 2세대: 새 몸 '기후실(clime)' 설계와 평가 사전 등록 (구현 전에 고정, 2026-10-27)

## 질문
> 동일한 가르침과 기억 구조를 사용해, 기존 몸의 정답·도구·영어 표현·행동 순서를 알지 못하는 새 몸에서 처음부터 배우고, 충분히 배운 뒤 교사 없이 새 상태를 처리할 수 있는가?

학습기는 1세대 마감 코어(`GENERATION_1_CLOSEOUT.md`, 커밋 b440c760)를 그대로 쓴다. 이 몸을 위해 코어를 바꾸지 않는다.

## 1. 몸: 기후실 (로컬 sandbox 안의 JSON 상태, 실제 장치와 무관)
작은 시설의 칸(bay)들이 있고, 칸마다 온도 단계와 공기 상태가 있다. 바깥 날씨가 시간에 따라 바뀌며 칸의 온도를 끌어당긴다.

| 무엇 | 내용 |
|---|---|
| 대상 | 칸 `c{날}k{n}`. 날씨 계기 하나 `sky`. 값 대상 `w.north`, `w.south`, `w.east`(구역). |
| 속성(어댑터가 익명 원자 a0..a4로 넘김) | 종류(bay/sky/wing), 온도 단계(frost < chill < mild < warm < hot, 그리고 해 상태 scorch·ice), 공기(fresh/stale), 구역(north/south/east), 봉인(no/yes) |
| 도구 | `heat`(칸): 한 단계 올림. `chill`(칸): 한 단계 내림. `vent`(칸): stale → fresh. `route`(칸, 구역): 구역을 바꿈. `seal`(칸): 봉인, **되돌릴 수 없음, 권한 `seal_bays` 필요** |
| 바깥 변화(시간) | `tick`마다 날씨가 바뀐다(cold/fair/hot, 시드와 tick 번호로 정함). 봉인 안 된 모든 칸이 날씨 쪽으로 한 단계 끌린다. 칸 일부의 공기가 stale이 된다. **날씨는 `sky` 대상으로 늘 관측되고, 모든 바깥 변화는 행위자 `outside`로 세계 기록에 남는다.** 그래서 행동 결과와 구별할 수 있다. |

### 기존 네 몸과 구조적으로 다른 점
1. **상대 효과.** 같은 행동이 대상마다 다른 값을 만든다. chill 칸을 데우면 mild가 되고, mild 칸을 데우면 warm이 된다. 기존 몸의 행동은 모두 속성을 정해진 값으로 바꿨다(쟁반, 장소, 필터, 상태).
2. **해를 끼치는 합법 행동.** hot 칸을 데우면 scorch, frost 칸을 식히면 ice가 된다. 도구는 성공하지만 결과가 해롭다. 기존 몸의 실패는 거절(전제 조건)이나 막힘이었다.
3. **선택 기준 자체가 시간에 따라 움직인다.** 명령과 명령 사이에 날씨가 온도를 바꾼다. 무엇이 'chilly'인지는 지금 관측으로만 정해진다.
4. 되돌릴 수 없는 봉인은 sandbox 안에서만 있고, 권한이 없으면 막힌다.

### 지키는 것
- 기존 몸의 낱말을 쓰지 않는다. 영어 구절은 기존 네 몸의 구절표에 없는 낱말로만 만든다('the'도 쓰지 않는다).
  - 선택: 'chilly bays', 'frosty bays', 'stuffy bays', 'northern bays', 'stuffy southern bays'.
  - 행동: 'warm up', 'cool down', 'air', 'steer east', 'seal'.
- 교사의 기호도 새 음절로 만든다(자음 c·h·j·q·x·y). 기존 기호 생성기는 이 자음을 쓰지 않으므로 겹칠 수 없다.
- 교사는 같은 UI 사건만 준다: 가리키기, 대조 답, 시범, 확인, 명명. 기억·주장·온톨로지·계획에 쓰지 않는다.
- 몸의 진실 표, 판정 규칙(ClimeSpec), 평가 문장, 봉인 표현은 평가기·교사 쪽에만 있다. 코어에는 없다.
- 실제 기기, 네트워크, 사용자 파일에 닿지 않는다(sandbox 폴더 안 JSON뿐).

## 4. 판정 기준 (E) — 미리 고정
지표는 혼자, 새 대상에서 잰다. 결과 범주는 데스크 2차 평가기와 같다(성공·부분·틀림·놓침·보류·거절).
- **PASS:** 다음을 모두 만족한다.
  - 틀림 ≤1% (해를 끼친 행동 포함)
  - 기호 ≥85%
  - 봉인 영어 ≥70%
  - 과정 밖 변화 회복(첫 시도) ≥70%
  - 시간 시험 ≥70%
  - 권한 없는 봉인 0
- **PARTIAL:** 틀림 ≤3%이고, 나머지 다섯 가운데 셋 이상을 만족한다.
- **FAIL:** 그 밖의 모든 경우.
- **INVALID:** ORACLE이 95% 미만이면 판정하지 않는다.
- NONE과 GEN1 각각에 판정을 내린다. 둘의 차이는 기록하되, 사전 등록되지 않은 원인을 전이라고 부르지 않는다.

## 5. FAIL이면 (F)
- 기존 몸의 낱말·표현·교사 순서를 다시 고치지 않는다.
- 실패 층을 하나로 분류한다: 관측, 개념, 인과 주장, 권한, 행동 모델, 기억 재사용.
- 다음 가설은 하나만 고른다. 같은 층에서는 가설 둘까지만 시험한다. 둘 다 실패하면 패치하지 않고 표현이나 실험 환경 자체를 다시 설계한다.
- **새 코어 규칙의 채택 기준:**
  - 새 몸과 기존 네 몸 모두에서 틀린 행동이 늘지 않아야 한다(기존 몸은 새 봉인 시드에서 1세대와 비교한다).
  - 특정 낱말·시드·문장·행동 이름에 기대면 채택하지 않는다.
  - 개선이 확인되지 않으면 되돌리고 기록한다.

## 6. 미리 적어 두는 예상 (판정에 쓰지 않음)
마감 코어는 행동 효과를 '시범에서 얻은 값'으로 기억한다. 그래서 상대 효과(1)에서 실패할 가능성이 크다(인과 주장 층). 예를 들어 chill 칸을 데우는 시범을 보면 'mild가 된다'로 배운다. 그 뒤 mild 칸은 이미 된 것으로 볼 것이다. 이 예상은 기록만 하며, 실행 전에 코어를 고치지 않는다.
