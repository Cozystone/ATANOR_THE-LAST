# 실제 사용자 교수 세션 (보드)

프로그램 교사(`teach/tutor.py`)는 회귀 시험과 자동 평가용이다. 이 문서는 **실제 사람**이 ATANOR를 가르치는 세션을 다룬다. 두 경험은 섞이지 않는다. 사람과의 경험은 사건·주장·온톨로지에 `source: human`으로 남고, 프로그램 교사의 경험은 `source: program`으로 남는다. 온톨로지에는 `learned_from → source:human` 연결이 있다.

## 안전
- 보드는 저장소 밖 sandbox 폴더의 JSON 파일 하나다(기본 `D:/ATANOR-experiments/2026-09-19/user-sandbox/board-1`). 실제 사용자 파일, 운영체제, 네트워크에는 닿지 않는다.
- 서버는 `127.0.0.1`에서만 듣는다. 외부 서비스나 언어 모델을 부르지 않는다.
- 카드 버리기(scrap)도 이 sandbox 안의 카드에만 일어난다.

## 실행
```bash
python -m atanor_os.ui.teach_server --root D:/ATANOR-experiments/2026-09-19/user-sandbox/board-1 --port 8765
```
브라우저에서 `http://127.0.0.1:8765`를 연다.

## 한 세션에서 하는 일
1. **새 세션.** 날이 바뀌었으면 "새 세션"을 누른다. 새 카드 8장이 들어온다. ATANOR는 기억으로만 이전 세션을 안다.
2. **가르치기.** 뜻하는 카드를 두 장쯤 가리킨다. ATANOR가 대조 질문("이 카드도요?")을 내면 답한다. 한 장에 행동을 직접 한 번 보인다. ATANOR가 나머지 카드에 하면 맞음/틀림을 확인한다. 틀리면 카드가 틀렸는지, 결과가 틀렸는지 고른다. 맞으면 원하는 기호를 붙인다(예: 선택 `mip`, 행동 `dax`). 처음에는 아무 뜻 없는 기호로 가르친다.
3. **이름 붙이기(나중에).** 이미 배운 선택이나 행동에 영어 같은 말을 붙인다. 말을 쓰고 "선택에 이름 붙이기"를 누른 뒤 카드를 가리키거나, "행동에 이름 붙이기"를 누른 뒤 한 번 보인다.
4. **명령.** 기호나 말로 명령하고 "혼자 하게 하기"(사람이 없는 것처럼) 또는 "내가 옆에 있을 때"(ATANOR가 대조 질문을 할 수 있음)를 고른다. 한 일을 맞음/틀림으로 판단한다. 확실하지 않으면 ATANOR는 하지 않는다(보류).
5. 오른쪽 "ATANOR가 배운 것"에서 각 기준과 행동의 근거(가리키기, 대조 답, 시범), 반례 수, 확신, 아직 가르지 못한 다른 기준, 붙은 이름을 본다.

## 10–20회 세션 계획(며칠에 걸쳐)
- 처음 2–3회: 선택 기준과 행동 서너 가지를 기호로 가르친다.
- 그 뒤 매 세션: 새 카드가 들어온 상태에서, 전에 가르친 기호로 혼자 하게 하기를 몇 번 한다. 가르친 짝과 처음 보는 조합을 섞는다.
- 며칠 간격을 둔다(같은 날, 1–2일 뒤, 3일 이상 뒤가 고루 나오게).
- 중간에 영어 이름을 몇 개 붙이고, 그 말로도 명령한다.

## 측정
```bash
python -m atanor_os.ui.session_report D:/ATANOR-experiments/2026-09-19/user-sandbox/board-1 --md <out.md>
```
- 수업: 확인된 비율, 수업당 가리키기·대조 답·시범 수.
- 재사용: 전 세션에 가르친 이름을 쓴 명령을 가르친 뒤 지난 날수와 혼자/함께로 나눈다. 성공·틀림·보류를 세고, 가르칠 때 없던 카드에서의 성공도 센다.
- 실패 분류: perception, grounding, structure, tool model, planning, safety hold, evaluator/env.
- 기억의 출처: 사람 대 프로그램.

## 규칙
결과가 나빠도 특정 낱말이나 문장에 맞춘 고침은 하지 않는다. 먼저 원인만 분류해 기록한다. 학습기 변경은 개발 시드에서 하고, 새 시드와 새 세션에서 따로 평가한다. 실제 세션의 결과는 실제 사람의 경험이므로, 프로그램 교사 평가와 섞어 보고하지 않는다.

## 시험 비행(사람 아님): 스크립트 사람으로 UI 경로 점검

`ui/pilot.py`는 실제 사람이 아니다. 출처를 `pilot`으로 남기고, 사람 결과로 보고하지 않는다. 화면의 사람이 답하는 질문(가리키기, 대조, 시범, 확인, 이름)에 같은 Session과 대기열로 답한다. 15회 세션을 시뮬레이션한 17일에 걸쳐 진행한다. 처음 3회는 기호로 수업하고, 8·10번째 세션에 영어 이름을 붙이고, 나머지는 명령이다(혼자와 함께를 번갈아). 개발은 시드 1에서 했다. 그때 시험 비행 자체의 결함(주지 않은 이름을 쓰는 것)을 찾아 고쳤다. 평가는 동결 스냅샷 g7에서 시드 7로 한 번 했다.

| 시드 | 명령 | 성공 | 보류 | 틀림 | 수업 확인 | 이름 붙이기(이미 배운 개념에) | 혼자, 가르친 지 7일+ | 실패 분류 |
|---|---|---|---|---|---|---|---|---|
| 1 (개발) | 46 | 45 | 1 | 0 | 5/6 | 8 (8) | 12/12 | 기준 없음 1, 개념 미결 보류 1 |
| 7 (평가, g7) | 46 | 45 | 1 | 0 | 6/6 | 6 (6) | 12/12 | 개념 미결 보류 1 |

- UI 경로(질문 대기, 시범 실행, 확인, 이름, 세션 넘김, 기록)는 15회 세션 동안 멈추지 않았다.
- 프로그램이 답한 결과다. 실제 사람의 가리키기와 대답은 더 흔들리고 틀릴 수 있다. 실제 세션의 결과는 따로 잰다.
