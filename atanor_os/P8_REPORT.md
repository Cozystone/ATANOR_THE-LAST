## 1. 무엇을 했나
**경험**
- 2026-10-24에 기록한 탐색 경험 22,500건이다(파일 몸 13,500건, 화면 몸 9,000건).
- 중복을 지우니 파일 몸 3,578건, 화면 몸 1,195건이 남았다.
- 시간 순서대로 앞 절반 E1과 뒤 절반 E2로 나눴다.

**원시 관측(사람이 준 감각)**
- 익명 속성 `a0…`과 익명 관계 `r0` 하나만 준다.
- kind, parent_kind, same_content 같은 사람의 개념 이름은 주지 않는다.
- 학습기 코드에 그런 이름이 없다는 것을 테스트로 확인했다.

**ATANOR가 한 일**
1. 원자(단항, 동등, 깊이 1 구조 합성) 위에서 성공과 실패를 대조해 규칙을 유도했다.
2. 여러 규칙에 되풀이되는 한 역할의 조합을 번호만 붙은 개념 `c_n`으로 만들었다.
3. 규칙을 그 개념으로 다시 쓰고, 바이트 예산 안으로 줄였다.
4. 학습 프로세스가 끝나면 **표현 파일만** 남겼다.
5. 시험은 그 파일만 있는 빈 폴더의 별도 프로세스에서 했다.

**만들어진 개념(파일 몸, 이름은 사람이 사후에 붙인 해석)**

| 개념 | 원자 | 사람 말로 하면 |
|---|---|---|
| `c0` | a0 = 1 ∧ a1 = 0 | "있고 디렉터리가 아님", 즉 사람이 말하는 *파일* |
| `c1` | 관련 객체 없음 ∧ a0 = 0 | "최상위에 없는 경로" |
| `c2` | 관련 객체의 a1 = 1 ∧ a0 = 0 | "디렉터리 안의 없는 경로", 즉 만들 수 있는 자리 |

이 중 4개가 두 도구 이상의 규칙에 재사용됐다(예: `c0`은 copy·move·delete·convert). **화면 몸에서는 개념이 하나도 생기지 않았다.** 그 몸의 규칙에는 한 역할에 대해 둘 이상의 원자가 되풀이되는 조합이 없었다.

## 3. 내부 표현이 실제로 더한 것 — 나눠서
1. **크기 제한 표현이 재시작을 견뎠다.** R1은 E1만으로 만든 1.9 KB 표현이다. 원래 기록은 수 MB다. 기록 없이 처음 보는 상황에서 예측 1.000, 과제 60/60과 20/20을 냈고, 전체 기록을 가진 FULL_STRUCT·FIXED와 같다. "기록을 다 들고 있어야 한다"는 가정은 이 범위에서 필요 없었다.
2. **그러나 그 성과의 원천은 개념 사전이 아니라 합성 원자다.** 사전 없이 합성 원자만 쓴 FULL_STRUCT도 1.000과 60/60이다. 반면 합성 원자가 없는 FULL_RAW는 0.823과 27/60이다. 개념 사전이 더한 것은 **압축과 재사용 구조**까지이고, 예측력은 아니다. 합성 원자 생성 규칙은 사람이 준 것이다.
3. **사례 검색 대비**: 예측은 비슷했지만(0.955) 계획에 쓰면 무너졌다(fs 27/60, view 7/20). 규칙형 표현이 행동에 더 쓸모 있었다.
4. **"짧아졌다"는 판정 근거가 아니다.** 크기는 보고만 한다.

## 4. 실패 지점 — 경험이 쌓일 때 개념과 규칙을 고치는 능력
R2(E2로 수정한 표현)가 R1보다 나빠졌다. fs 예측은 1.000에서 0.970으로, view는 1.000에서 0.863으로, fs 과제는 60/60에서 20/60으로 떨어졌다.

**원인**
- 수정은 **E2만으로** 규칙을 다시 유도했다. E2에 우연히 없던 반례 때문에 과도하게 일반화된 규칙이 생겼다.
  - 화면 몸 close: E2에 close 실패가 없어 조건이 **빈** 규칙("언제나 성공")이 생겼다 → fp 20.
  - 파일 몸 move: E2에 "디렉터리를 옮기기" 실패가 없어 "원본이 파일"(`c0`) 조건이 빠졌다 → fp 3. 그 결과 sort·convert 과제가 전부 실패했다.
- 새 규칙은 지지 수가 더 커서, 맞는 옛 규칙보다 먼저 선택됐다.
- 표현은 규칙만 남기고 **그 규칙을 정당화한 반례**는 남기지 않는다. 그래서 수정 단계는 "이 조건이 필요 없다"와 "E2에서 시험된 적이 없다"를 구별하지 못한다.

**다음 병목**: 크기 제한 안에서 **증거(어떤 조건이 실패로 확인되었는지)를 함께 남기는 표현**과, 확인된 조건을 새 증거 없이 지우지 않는 수정 규칙. 다음 단일 가설로 제안하며 아직 시험하지 않았다.

## 5. 주장할 수 있는 것 / 없는 것
- **있다**
  - ATANOR는 사람 개념 이름 없이 경험에서 번호 개념을 만들었고, 그것을 여러 도구에 재사용했다("파일", "만들 수 있는 자리"에 해당하는 구분).
  - 그 개념으로 쓴 1.9 KB 표현이 재시작 뒤 기록 없이 처음 보는 상황에서 전체 기록 조건과 같은 예측·행동을 냈다(R1).
- **없다**
  - 개념 사전이 예측력을 더했다는 것: FULL_STRUCT와 같다.
  - 경험이 쌓일 때 개념을 올바르게 고친다는 것: R2가 R1보다 나쁘다.
  - 화면 몸에서 개념이 생겼다는 것: 0개다.
  - 언어가 생겼다는 것.
- 사전등록 판정은 INCONCLUSIVE다. R1의 좋은 결과는 1차 조건이 아니므로 판정을 바꾸지 않는다.
