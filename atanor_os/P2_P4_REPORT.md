## 1. 선택한 변경과 이유

P1이 남긴 질문은 셋이었다: (a) C의 남은 실패가 **획득**(어떤 경험을 모으는가) 문제인가, (b) 같은 학습기가 **다른 몸**에서도 배우는가, (c) 이 루프가 **죽어도 되는 운영자**로 돌 수 있는가. 각각을 한 가설씩으로 좁혔다.

- **P2 · H1 획득 정책** — 탐색 정책만 바꾼다(성공이 적은 도구 우선 + 성공 서명과 한 리터럴 차이인 미시도 서명 우선 = `contrast`). 학습기·planner·예산 무변경. 절제 `scarce`(도구 가중만).
- **P2 · H2 스킬** — 스스로 완수한 훈련 에피소드에서 "인자 구조가 연결된 연속 도구 쌍"(매크로)을 뽑아 계획에 넣는다(E). 같은 훈련 경험만 더한 CT와 비교해 매크로의 기여만 분리.
- **P3 · H3 전이** — 두 번째 몸(화면 패널 명세 + UI 도구)을 만들고 **학습기 코드를 한 줄도 몸에 맞추지 않은 채** 규칙을 배우는지 본다. 신뢰된 렌더러와 제한된 한국어 문법은 사람이 준 것으로 분리.
- **P4 · 감독 루프** — 한 journal 아래 과제 흐름을 돌리는 운영자. 임의 시점 kill 뒤 재시작 시 "기억"이 아니라 **실제 상태**를 다시 관측해 의도와 대조하고 재개한다. 로컬과 HP 노트북에서 실측.

이유: 세 질문이 서로 다른 실패 축(획득·표현·운영)이라 한 번에 하나씩 바꿀 수 있고, 각각 사전등록 가능한 판정 규칙이 있다.

- **사전등록 파일**: `protocol.json` v3(H1), `protocol_h2.json` v4(H2), `protocol_view.json` v1(H3). 모두 해당 실행 전에 동결(`DECISIONS.md` 순서).

## 4. 구현한 경로와 재현 명령 (구현됨·시험됨)

테스트 31개(`python -m pytest atanor_os/tests -q`): 누출·세계·평가기·학습·스킬·화면 몸(의미론·진실 모델 일치·렌더러·문법·규칙 일치)·감독자(대조·재개·프로세스 kill).

```
python -m atanor_os pilot --split test --seeds 1,2,3,4,5 --tasks 20 --steps 300 --conditions A,B,C --policy contrast --out atanor_os/results/p1-test-03-contrast
python -m atanor_os compare --a atanor_os/results/p1-test-03-contrast --b atanor_os/results/p1-test-02 --cond C           # H1
python -m atanor_os pilot --split test --conditions A,B,C,CT,E --policy contrast --protocol atanor_os/protocol_h2.json --out atanor_os/results/p2-h2-01   # H2
python -m atanor_os pilot --body view --steps 600 --policy contrast-kind --conditions A,B,C --split test --out atanor_os/results/p3-view-01   # H3
python -m atanor_os crash --root atanor_os/runs/crash --experiences atanor_os/results/p1-test-03-contrast/explore/experiences_s1.jsonl --episodes 40 --kill-min 0.5 --kill-max 3
python -m atanor_os supervise --root atanor_os/runs/sup --experiences <같은 파일> --episodes 200                                   # P4
```

구현 변경 요약(모두 `DECISIONS.md`에 이유 포함): 학습기 v3(인자 유형 그룹 → 선택지 전제조건), v4(효과 가설 언어 `lift.effect_candidates`: 비식별 속성 상수 → 다른 역할의 **모든** 속성 복사; 그룹 공유 선택 우선), 탐색 `contrast-role`·`contrast-kind`, 화면 몸·렌더러·문법, 스킬 추출, 감독자·충돌 시험, 평가기 `rule_agreement`·몸별 프로토콜·판정 일반화·소스 식별.

### 5.2 scarce 절제 — `results/p1-test-03-scarce` (INVALID) · `…-scarce-rerun` (VALID_BOUNDED_GAIN)
1차 실행은 실행 시작 시점의 유효성 테스트가 실패해 사전등록 규칙상 **INVALID**. 원인은 학습기가 아니라 **공정**: 같은 작업 트리에서 화면 몸을 개발하는 동안 그 테스트들이 깨져 있었고 파일럿이 그 순간 pytest를 돌렸다. 재발 방지(스냅샷에서 실행·소스 sha256 시작/종료 기록)를 넣고 동일 프로토콜·seed로 1회 재실행했다 — **재실행 결정은 1차 수치(C 1.00)를 본 뒤 내린 것**임을 명시한다.

재실행(스냅샷 sha 6ac1457be2fcf22c, 테스트 통과): **C 1.00 · B 0.36 · A 0.20 · ORACLE 1.00**, C−B +64 pp(5/5). v2(novelty) 대비 **+16 pp**(seed 2 +50·seed 3 +30·나머지 0, 과제 16/84/0) — contrast의 +10보다 크다. 해석: fs에서 유효 성분은 **"성공이 적은 도구를 우선 시도"(도구 가중)**이고, 도구 내부의 대조 우선은 더하지 못했다(contrast의 sort 0.83 vs scarce 1.00). H1의 사전등록 문구는 두 성분을 함께 가설로 세웠으므로 "H1 GAIN"은 유지되지만 **기여는 절제군에 있다**.

1차 실행과 320 에피소드 중 314가 행동 순서까지 같았고, 다른 6개(seed 1 C convert)에서 **학습기의 순서 의존성**이 드러났다: 같은 탐색 로그에서 옛 학습기는 `parent_kind(1)=dir`을, v4는 `kind(0)=file`을 남겼다 — 둘 다 관측된 실패 119건과 일치하고 둘 다 참 조건이지만 "하나만 지워도 되는" 상황에서 어느 쪽을 지우는지가 제거 순서로 결정됐다. 완수는 같았지만(1.00) convert를 없는 디렉터리에 먼저 시도해 행동을 낭비했고 규칙 일치는 4/5. 순서 무관한 정의 두 가지(경쟁 리터럴 보존 / 최소 설명들의 합집합)를 시험했으나 저데이터 구간에서 상관된 리터럴이 함께 남아 일반화를 죽였다(fs 20→13/20, 화면 dev 12→3/12) — **기각**, 학습기는 v4 유지. 이 한계는 학습기 편향으로가 아니라 **대조 획득의 표적화**(§6)로 풀어야 한다는 것이 이 실험의 교훈이다.

### 5.3 화면 몸에서 C < A/B 였던 원인 (헌장 §6) — dev 분할, 결과를 본 뒤의 수정이므로 test는 §5.4에서만
처음 화면 몸 dev 실행: A 12/12, B 12/12, **C 9/12** — compare 과제 3건 전부 `planner_budget_exceeded`.
- **표현 결함(주원인)**: 효과 가설 언어가 `hash`/`value`의 복사만 허용 → "compare 패널이 원본 패널의 filter/sort를 상속"을 표현할 수 없어 효과가 `unknown`으로 붕괴 → 목표 `filter(cmp)=e`가 C의 세계 모델에서 도달 불가 → 40만 예측 소진. A/B는 설명서가 그 효과를 말하지 않아 쓸모없는 `filter(cmp, …)`를 시도하다 **실제 상속 덕에 우연히 성공**(A no-op 3.6/에피소드).
- **학습 결함(부원인)**: 성공 공통 리터럴의 단일 논리곱으로는 "panel 또는 compare"(close·sort)를 표현 못 함.
- **획득 결함**: 희소 도구 group은 성공이 0이면 대조 후보가 없어 신규성 탐색이 15×14 인스턴스 공간을 헤맸다(seed 2·3: 255·184회 시도, 성공 0).
수정: 학습기 v3(유형 그룹 선택지) + v4(임의 속성 복사 효과, 그룹 공유 선택) + 정책 `contrast-kind`(성공 없는 도구는 인자 **kind 튜플** 수준에서 최소 시도 조합 우선). 중간에 "상수 우선 + 그룹별 선택"의 조합이 filter 규칙을 값마다 다른 상수 그룹으로 쪼개는 퇴행(dev C 0/12)을 만들었고, 공유 선택으로 고쳤다. 결과 dev C 12/12. **fs 회귀**: 기록된 C 80 에피소드(p1-test-02 seed 1·2, p1-test-03-contrast seed 1·3)의 행동 순서·성공 여부가 비트 단위 동일 — v2→v4가 fs 결과를 바꾸지 않았다.

## 6. 다음 한 가지 변경 가설

P2–P4가 일관되게 가리키는 것: 남은 실패와 낭비의 원인은 학습기의 편향이 아니라 **어떤 경험을 모으는가**다. scarce가 contrast를 이겼고(§5.2), 훈련 에피소드 20개가 seed 2의 규칙 구멍을 메웠고(§5.5), 화면 몸 seed 5의 비정확 규칙 두 개는 모두 "성공 1건" 조합이었고(§5.4), 순서 의존성은 "둘 중 하나만 지워도 되는" 모호함을 데이터가 못 가르는 데서 왔다(§5.2).

**가설 H4(표적 대조 획득):** 탐색 정책이 학습기의 현재 규칙에서 **모호한 리터럴 쌍**(둘 중 하나만 제거해도 관측 실패와 일치하는 경우)과 **지지가 1인 유형 그룹**을 읽어, 그 리터럴 하나만 뒤집은 상황·그 유형 조합을 우선 시도하면, 같은 단계 예산(fs 300·view 600)에서 (i) 모호한 쌍이 남은 도구 수가 ≥ 4/5 seed에서 0이 되고 (ii) 규칙 일치가 fs 5/5·view 6/6 도구에 모든 seed에서 도달한다.
- 이것은 획득 정책이 학습기를 **읽는** 첫 정책이다(지금까지의 정책은 탐색 기록만 봤다). 헌장 §5가 허용하는 능동 획득이며, 평가기 진실에는 접근하지 않는다.
- 측정: train/dev에서 커버리지·규칙 일치로 정책 선택 → `protocol.json` v5 / `protocol_view.json` v2로 동결 → test 1회. 1차 지표는 규칙 일치(도구별 fp/fn/eff), 2차는 완수·no-op·예측 횟수.
- 기각 시: 모호함은 탐색으로 해소되지 않는 **표현** 문제(예: 두 리터럴이 세계에서 항상 함께 참)로 보고, 학습기가 모호한 쌍을 규칙에 명시적으로 **보존·표시**(unseparable처럼)하는 쪽으로 간다.
- 보류: 매크로 열거 비용(§5.5)과 증분 규칙 유도(§5.6)는 공학 과제로 분리해 H4와 섞지 않는다.

P2의 가설 변경 상한(3회)은 H1·H2로 2회를 썼다. H4는 세 번째다.
