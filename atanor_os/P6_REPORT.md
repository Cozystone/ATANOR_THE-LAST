## 1. 선택한 구현과 이유
사용자가 정한 범위는 세 가지다: 훈련 중에만 교사 사용, 평가 중 교사 호출 0, 공개 웹 읽기 전용.

과제는 "작업 공간에서는 관측할 수 없고 공개 문서에만 있는 사실이 있어야 풀리는 파일 정리"다. 구체적으로, 파일마다 그 형식의 **공식 명칭**을 찾아 아래 세 가지 중 하나로 처리한다.
1. 명칭 이름의 폴더로 이동한다.
2. 파일 이름을 명칭으로 바꾼다(확장자 유지).
3. 명칭 이름의 폴더로 복사한다(원본 유지).

이 과제를 고른 이유는 두 가지다. 이미 경험으로 배운 파일 몸으로 행동할 수 있고, 평가기가 진실(Wikidata 스냅샷)로 판정할 수 있다.

v1 과제(확장자 → 미디어 타입)는 평가기 작성 응답이 **안전 분류기에 의해 중단**되었다. 분류기는 사유를 알려 주지 않는다. 지시대로 그 내용을 재구성하지 않았고 무해한 과제로 교체했다. v1 프로토콜은 `protocol_p6_v1.json`으로 보존했다.

## 3. 과제·비교군·예산·누출 방지·봉인
- **과제**: 가능 과제 30개(형태별 10개)와 불가능 과제 6개. 각 과제에 파일 3개와 건드리면 안 되는 하위 폴더 파일 1개가 있다. 불가능 과제에는 무작위 5글자 확장자 파일이 섞여 있다.
- **진실**: Wikidata 스냅샷의 형식 48개를 sha256 규칙으로 훈련 16개와 평가 32개로 나눴다. 교사는 평가 풀을 열지 않았다. 훈련 전용 추가 형식 60개는 평가 풀과의 교집합이 0이다.
- **비교군**:

| 조건 | 내용 |
|---|---|
| F | 전체: 웹 + 두 페이지 일치 시 채택 |
| S | 웹 + 첫 신뢰 페이지 채택 |
| M | 훈련 기억만 |
| N | 기억·웹 없음 |
| ORACLE | 진실 명칭 + 정답 형태 |

- **예산**: 사실 하나당 검색 3회와 페이지 6개까지.
- **웹 매너**: 요청은 GET만, 같은 호스트에는 1초 이상 간격, `robots.txt`를 지킨다.
- **봉인**: 메인 세션과 문맥을 공유하지 않는 에이전트가 평가 문장 30개를 쓰고 sha256만 돌려주었다. 교사는 평가가 끝날 때까지 개수만 확인했다. 이 봉인 파일은 동결 커밋에 함께 들어가 평가 전에 공개되었다. 교사가 읽지 않았다는 점은 변하지 않지만, 문장이 평가 전부터 공개 레포에 있었다는 사실은 밝혀 둔다. **이것은 강한 의미의 비공개 평가가 아니다**(사용자 지적, 2026-10-24). 이후에는 원본을 레포 밖에 두고 실행 전에는 해시만 공개한다.
- **누출 방지**: `agent/`·`core/`·`world/`는 `eval/`·`teach/`·`mimetypes`를 import하지 않고, Wikidata 쿼리 서비스나 LLM 엔드포인트 문자열도 담지 않는다(테스트). 평가 프로세스에서는 import 가드와 호스트 차단이 동작한다.

### 5.2 불가능 과제에서 멈추는 능력
F는 6/6에서 무작위 확장자 파일을 건드리지 않고 "근거 없음"으로 멈췄다. 하지만 **N도 6/6**이다. 이 과제에서 F는 처음 보는 **모든** 형식 앞에서 멈췄으므로, 이 6/6은 "모를 때 멈춤"과 "알아도 멈춤"을 구별하지 못한다. 멈춤 능력의 증거로 쓰지 않는다.

### 5.3 출처가 엇갈릴 때의 판단
- F는 평가에서 서로 다른 형식 37개를 만났다.
- 결과: 근거 없음 31개, 단일 출처 5개, 모순 1개. 평가 중 새로 채택한 명칭은 0개다.
- **모순**(`.proto`): 위키백과 문서는 "Protocol Buffers", protobuf.dev 페이지는 "Language Guide"를 1위로 뽑았다. 두 값이 달라 그 파일을 두고 멈췄다.
- **단일 출처 5개**: 그대로 채택했다면 2개는 맞고(`jng` "JPEG Network Graphics", `xbm` "X BitMap") 3개는 틀렸다(`wbmp` "Mozilla Firefox", `f3b`, `bie` → 인명).
- **S는 이 차이를 직접 보여준다.** S는 `wbmp`를 "Mozilla Firefox"로 세 번 채택해 파일 3개를 잘못 놓았다. F는 같은 상황에서 두 번째 출처가 없어 멈췄고 잘못 놓은 파일이 0이다.
- 즉, 두 출처 일치 규칙의 측정된 가치는 완수가 아니라 **오류 방지**다(F − S: 완수 0 pp, 잘못 놓기 3 → 0).

### 5.5 정확한 장애 지점
1. **읽기(주원인)**
   - F가 연 페이지 111곳 가운데 1위 후보가 정답인 곳은 15곳, 형식 수로는 11개였다.
   - 하지만 두 번째로 일치하는 페이지가 없거나 신뢰 점수가 보정 임계값 아래여서 하나도 채택되지 않았다.
   - 훈련 자료로 상한을 재 보면, 보관한 페이지에서 정답 명칭이 두 곳 이상의 후보에 오르는 형식은 약 25%뿐이다.
   - 후보 생성(대문자 구·정의문 주어)과 다른 언어 문서로 새는 탐색이 한계를 만든다. LLM 없이 실제 문서의 문장을 읽는 능력은 이 과제에서 모자랐다.
2. **목표 해석(부원인)**
   - 처음 보는 문장 36개 가운데 24개(0.67)만 맞았다. 형태별로 folder 7/12, rename 7/12, copy 10/12.
   - 혼동은 rename → copy 5번, folder → copy 5번, copy → folder 2번이었고, 2개는 "불명확"으로 멈췄다.
   - 교사의 문장 36개로 배운 어휘가 봉인된 표현의 다양성을 따라가지 못했다.
   - 웹에서 미지어 의미를 찾는 기능은 작동했지만(예: dev에서 "carries"), 해석을 바로잡을 만큼은 아니었다.
3. **검색 진입점**
   - 정직하게 쓸 수 있는 진입점이 Wikimedia·Wiby로 좁다.
   - robots 거부가 F 요청의 8%였다.
   - 따라서 이 결과는 **열린 인터넷 전반을 탐색한 결과가 아니다.**

### 5.6 차단과 외부 제한으로 빠진 범위
- v1 과제 평가기: 안전 분류기 중단으로 v2로 교체했다(위 §1).
- 일반 검색엔진: DuckDuckGo는 CAPTCHA를 낸다. Bing·Google·Startpage·Mojeek·Marginalia는 `robots.txt`로 검색 페이지를 막는다. 어느 쪽도 우회하지 않았다.
- `experiment`(샌드박스 리허설): 구현했고 시험도 통과했지만, 평가에서는 채택된 명칭이 없어 **한 번도 실행되지 않았다.** 이 단계에서는 "실험을 설계·실행한다"는 부분을 시험하지 못했다.

### 5.7 주장할 수 없는 것
- ATANOR가 스스로 부족한 정보를 찾아 낯선 일을 해냈다는 것. 이번 결과는 그 반대다: 찾아 나서고 엇갈림을 알아차려 멈추기는 했지만, 일을 완수하지 못했다.
- 자유로운 영어 이해, 연속적인 삶, 주체적 사고.
- 불가능 과제의 6/6을 판단력으로 해석하는 것(§5.2).

## 6. 다음 한 가지 변경 가설
측정된 병목은 **읽기**다. 사용자가 허용한 범위(훈련 중 교사, 평가 중 제거) 안에서 가장 직접적인 다음 변경은 하나다.

> **H6-1(구간 단위 교사 주석):** 훈련 중 교사가 ATANOR가 고른 페이지에서 "명칭이 쓰인 위치"를 표시하고, 오해하기 쉬운 반례 페이지(같은 약어의 다른 대상)를 만들어 준다. ATANOR의 후보 생성과 신뢰 판단을 이 구간 감독으로 학습하면, 교사를 끈 평가에서 처음 보는 형식의 채택 정밀도가 0.9 이상이고 완수가 N보다 30 pp 이상 높아진다.

- 같은 과제와 진실을 쓰되, 새 평가 문장과 새 seed로 새 프로토콜(v3)을 동결한다.
- 목표 해석은 같은 방식으로 교사의 표현 다양화와 반례를 늘리고 처음 보는 표현에서 다시 잰다.
- 실패하면 "제한된 학습기 + 제공된 후보 생성기"로는 실제 문서 읽기가 안 된다는 결론을 남긴다. 그 경우 언어 이해를 어디서 얻을지(교사 의존을 남길지)를 다시 결정해야 한다.
