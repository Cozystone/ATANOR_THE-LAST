# ATANOR 재설계 계획 (2026-10-28)

이 계획은 사용자의 2026-10-28 재설계 지시를 따른다. 이 지시는 이전의 가지별 진행·대기 지시를 대체한다.
- 4세대 B2(선택적 질의)는 구현 전에 이 지시로 대체됐다. 봉인 세트 `gen4b2_sealed.json`은 만들었지만 한 번도 쓰지 않았다. 그래서 다른 실험의 봉인 세트로 다시 쓰지 않는다.
- 모든 결과는 **프로그램 교사가 제한된 디지털 몸에서 가르친 결과**다. 실제 사람 결과가 아니다. 실제 사람 세션은 0회다.
- 이 계획은 완성이나 AGI 도달을 약속하지 않는다.

## 1. 관측된 실패 → 원인 가설 → 설계 변경 → 평가

|---|---|---|---|
| E 기각: 합친 해석이 '이미 됐는가'를 결과 값 하나로 판단해 기후실 틀림 19 → 27 (`GEN3_E_RESULTS.md`) | 행동의 정체와 결과가 한 노드에 묶여 있다. 결과는 시작 상태의 함수인데, 노드에는 값 하나만 있다 | 행동의 식별(도구 + 상수 인자)과 결과의 예측을 분리한다. 결과는 출력마다 시작 상태의 조건부 함수로 둔다(`rebuild/effects.py`) | 2단계 예측 벤치마크 |

| B1: 사례 없는 대상의 갈림을 사람 답 하나가 정한다. 그러나 질문 경로가 행동 규칙 안에 섞여 있다 (`GEN4_B1_RESULTS.md`) | 불확실성이 '보류'로만 끝나고, 무엇을 확인하면 풀리는지가 남지 않는다 | 미해결 문제를 기록으로 남긴다(필요한 판단, 경쟁하는 설명, 확인 후보, 비용과 위험, 재개 조건). 단순한 확인 정책이 후보를 고른다 | 3단계: 무작위, 항상 질문, 항상 보류와 비교 |
| 사람의 확인·거절과 시간 뒤 결과를 판단에 쓰지 않는다 (`GENERATION_3_STATUS.md`) | 거절의 범위(대상 선택, 결과, 실행 불허)가 기록되지 않거나 섞인다 | 답마다 적용 범위를 기록한다. 범위가 불분명한 답은 넓은 금지나 승인으로 저장하지 않는다 | 1단계 재현, 4단계 |

## 2. 고정하는 것
- 기존 몸의 관측 인터페이스, 안전 경계(기후실 해 경계, 권한), 교수 UI, 저널·복구 기능.
- 기준 코어는 `atanor_os/agent/grounding.py`(1세대 마감 코어 + G + H1, 동결 g58과 같음)이다. 비교 대상으로 그대로 둔다.
- 새 학습기는 `atanor_os/rebuild/`에 따로 만든다. 검증된 부분만 기준 코어와 바꾼다.
- 하지 않는 것:
  - 픽셀 지각, HDC, 새 OS, 새 몸 대량 추가.
  - 옛 ATANOR·BITMIND를 통째로 가져오기.
  - LLM이 예측·선택·기억 갱신을 대신하기.

## 3. 새 구조 (최소 구현부터)
- **A. 경험** (`rebuild/experience.py`). 다음을 서로 다른 필드로 보존한다.
  - 행동 전 관측과 시각
  - 행동·인자·부여 권한
  - 실제 실행 여부와 몸의 응답('ok' / 'failed' / 'blocked')
  - 직후 관측과 나중 관측
  - 알려진 외부 변화
  - 목표, 그리고 답과 그 적용 범위
  - 관측하지 못한 것

  나중 변화는 행동의 효과로 넣지 않는다. 도구 성공, 목표 달성, 승인, 안전을 한 값으로 합치지 않는다.
- **B. 조건부 효과** (`rebuild/effects.py`). 출력마다(몸의 응답, 각 인자의 각 속성) 사례와 모순되지 않는 설명을 모두 유지한다.
  - 설명의 종류: CONST, COPY(입력 v), TABLE(입력 집합 S, |S| ≤ 2).
  - 예측 조건: 가장 단순한 설명들이 모두 이 시작을 본 적이 있고, 서로 같은 답을 낸다. 한 단계 더 복잡한 설명이 '시도해 본 적 없는 조건'(변한 적 없는 입력의 새 값, 있음/없음의 바뀜) 때문에 이 시작을 덮지 못하면 예측하지 않는다.
  - 예측하지 못하면 '모름'과 경쟁하는 값을 낸다.
  - 시작이 같은데 결과가 다른 사례는 세계가 바뀐 증거로 본다. 앞 사례는 반례로 남기고, 더는 맞추는 데 쓰지 않는다.
  - 비교 대상은 EXACT(같은 시작만), LAST(같은 시작, 없으면 가장 최근 사례), CORE(첫 시범의 변화. 기준 코어의 효과 주장과 같다)다.
- **C. 목표 적합** (`rebuild/goals.py`). 사람의 답을 '그 행동, 그 개념, 그 대상의 시작'에 대한 사례로 둔다. 같은 설명 틀로 예측한다. '아니오'는 대상 선택 오류, 결과 불만족, 실행 불허로 나눠 둔다. 범위가 불분명하면 그 정확한 사례로만 둔다.
- **D. 미해결 문제와 확인 정책** (`rebuild/inquiry.py`).
  - 확인 후보:
    - 실험실 사본 시험: 비용 1, 위험 0. 몸이 실험실을 줄 때만.
    - 사람에게 묻기: 비용 q. 사람이 있을 때만.
    - 보류하고 다른 일을 진행하기.
  - 정책: 결정을 바꿀 수 있는 모름만 확인한다. 효과를 모르면 실험실, 목표 적합을 모르면 질문, 둘 다 안 되면 보류한다.
  - 비교 정책: 무작위, 항상 질문, 항상 보류.
  - 미해결 문제는 파일로 남아 재시작 뒤에도 이어진다.
- **E. 언어.** 이번 단계에서는 기준 코어의 낱말 연결을 그대로 쓴다.
  - 상태 보고는 '사람이 쓴 틀 문장'과 'ATANOR이 배운 낱말'을 구분해 표시한다.
  - `why`·`error` 출력으로 사고나 언어 이해를 주장하지 않는다.

## 4. 개발과 평가
- **개발 자료:** 다섯 몸 × 과정 시드 1–5(평가 세계 101–105). 시드 하나에 맞추지 않는다. 판정은 다섯 시드 합과 몸별로 함께 본다.
- **최종 평가 자료(개발에 쓰지 않음):** 과정 시드 931–933, 평가 세계 1031–1033. 각 단계의 판정 기준을 고정한 뒤 한 번만 연다. 연 뒤에는 회귀 자료로만 쓰고, 봉인 평가라 부르지 않는다.
- **1단계 — 경험 계약과 최소 재현.** 기존 로그에서 혼동 사례를 뽑는다. 상태 의존 효과, 외부 변화, 실행 성공과 목표 실패, 범위가 불분명한 거절. 로그에 없는 정보는 부족하다고 표시한다.
- **2단계 — 행동 전 예측.** 같은 경험, 같은 질의에서 비교한다. 이미 본 시작, 새 조합, 새 값을 나눠 잰다. 정답률(전체 대비)과 응답 범위를 함께 잰다. 항상 '모름'이면 정답률이 0이므로 통과하지 못한다.
  - 판정 기준(최종 평가 전에 고정): 몸마다 다섯 시드 합에서
    1. NEW의 틀림이 EXACT보다 많지 않다(0이어야 한다).
    2. NEW의 정답률이 EXACT보다 높다.
    3. 틀림이 있는 LAST·CORE보다 정답률이 5%p 넘게 낮지 않다. 낮으면 '적게 틀리지만 일을 덜 한다'로 기록하고 채택하지 않는다.
- **3단계 — 정보 획득.** 같은 과정 뒤, 모름이 남은 질의에서 각 정책이 확인을 고른다.
  - 잰다: 확인 횟수(실험실·질문), 위험(실제 세계에서 모르고 한 행동), 추가 경험, 그 뒤 혼자 맞게 예측한 비율.
  - 교사가 정답을 그대로 준 효과(ORACLE, 모든 질의에 정답 제공)와 질문 선택의 효과를 분리한다.
- **4단계 — 실제 행동과 지속성.** 기존 몸과 기존 평가기에서 기준 코어와 비교한다.
  - 잰다: 완수, 오류, 부분 수행, 보류, part-held(성공으로 세지 않음), 비용.
  - 재시작(명령마다 새 학습기), 환경 변화(규칙 바뀜, 외부 변화), 교사 부재(혼자 평가)를 포함한다.
  - 몸의 경계가 막은 행동과 ATANOR이 스스로 피한 행동을 따로 센다.
- **5단계 — 통합.** 입증된 부분만 기준 코어와 바꾼다. 성과가 없으면 성공으로 포장하지 않는다. 표현과 정보 가운데 무엇이 부족했는지 먼저 확인한다.

## 5. 규칙
- 단위 테스트 통과와 새 능력은 다르다. ORACLE 통과만으로 평가가 옳다고 결론 내리지 않는다.
- 사전등록 판정과 실제 채택 판단은 따로 적는다. 오류가 줄어도 일을 거의 하지 못하면 채택하지 않는다.
- 몸별 개선과 퇴행을 함께 적는다.
- 같은 실패에 예외 조건을 되풀이해 붙이지 않는다. 같은 원리의 수정이 두 번 실패하면 원인, 표현, 자료의 적합성을 검토한다.

## 6. 개발 기록 (개발 시드 1–5만)
- 2026-10-28, `effects.py`의 세 판본을 개발 시드에서 비교했다(네 몸, 9,210개 질의).
  1. 한 단계 더 복잡한 설명이 모두 덮어야 하는 판본(NEW1): 틀림 0. 새 조합의 정답이 적었다(기후실 192/578).
  2. 가장 단순한 설명만 덮으면 되는 판본(NEW0): 새 조합은 다 맞혔다. 대신 새 값에서 틀렸다(데스크 500, 기후실 148, 보드 136).
  3. 둘 사이 판본: 한 단계 더 복잡한 설명은 '시도한 적 없는 조건' 때문에 못 덮을 때만 막는다.
     - 처음에는 '변한 적 없는 입력의 새 값'만 시도한 적 없는 조건으로 봤다. 그러자 보드에서 81건이 틀렸다. 모두 쟁반에 없는 카드('-')를 꺼내는 경우였다.
     - '있음/없음이 바뀐 값'(관측 인터페이스의 '-')을 더했다. 그 뒤 네 몸 모두 틀림 0이 됐다.
- 이 바꿈은 개발 시드에서 한 것이다. 최종 평가에서 다시 확인한다.
- 같은 날, 규칙을 덧붙이는 방식을 멈췄다(규칙 5: 같은 원리의 수정을 되풀이하지 않는다).
  - 위 판본에 오류가 다시 나왔다. 보드 실험(3단계)에서 새 사례를 더하자 틀림이 생겼고, 교사가 모든 정답을 줘도 정답률이 떨어졌다.
  - 원인은 표현의 한계였다. 칸마다 '상수 또는 한 입력의 복사'를 고를 수 없었고, 두 입력을 넘는 조건을 아무 설명도 맞추지 못했다.
  - 그래서 하나의 원리로 바꿨다(`effects.BayesAction`). 입력 집합 S(크기 0–2)마다 칸을 나누고, 각 칸을 상수 또는 복사로 본다. 설명마다 사례의 주변 우도를 매기고, 크기마다 같은 사전 확률을 준다. 예측 분포가 τ 이상일 때만 답한다. 입력에는 '값이 있는가'(관측 인터페이스의 '-')를 더했다.
  - 같은 시작이 사례에 있으면, 맞는 설명이 없어도 그 결과를 쓴다.
- 행동 정체도 바꿨다. 상수 인자는 '여러 다른 인자와 함께 쓰였고 한 번도 바뀌지 않은 인자'이며, 위치는 상관없다. 데스크 `shelve`는 폴더가 첫 인자다. 상수 집합이 바뀌면 모든 사례를 다시 묶는다.
- 평가기 버그도 고쳤다. 파일 몸에서 지워진 파일을 경로로 관측해, 과정 로그('-')와 표기가 달랐다.
- **고정한 판본(최종 평가 전):** `BAYES`, τ = 0.99.
  - 개발 시드 1–5, 다섯 몸 합의 정답률과 틀림:

    | 몸 | 정답률 | 틀림 | LAST 정답률 (틀림) | EXACT 정답률 |
    |---|---|---|---|---|
    | 보드 | 0.617 | 0 | 0.624 (467) | 0.353 |
    | 기후실 | 0.698 | 0 | 0.662 (856) | 0.510 |
    | 데스크 | 0.434 | 3 | 0.450 (2,728) | 0.339 |
    | 파일 | 0.882 | 0 | 0.176 (700) | 0 |
    | 화면 | 0.186 | 0 | 0.186 | 0.171 |

  - 데스크의 틀림 3개는 모두 '잠긴 메시지'를 보관하는 경우다. 학습 과정에서 상태가 여러 번 바뀌었지만 결과에 상관이 없었고, '잠김'이라는 값만은 본 적이 없었다. 몸은 그 호출을 거부한다(해 없음).
  - τ = 0.999로 올려도 고쳐지지 않았다. 사례로는 알 수 없는 귀납의 한계로 기록한다.
- **2단계 판정 기준 수정(최종 평가 전, 이유 기록).** 기준 1 'NEW의 틀림 0'을 '몸마다 틀림 비율 0.2% 이하'로 바꾼다. 위 개발 결과(데스크 0.06%) 때문이다. 기준 2·3은 그대로 둔다.
- **3단계 판정 기준(최종 평가 전 고정).** 몸마다 세 시드 합에서, 확인 횟수가 같을 때(세계당 K = 10) 다음을 본다.
  1. CHOOSE의 틀림이 HOLD보다 많지 않다.
  2. CHOOSE의 '이후 혼자 정답률'이 HOLD보다 높다(확인이 쓸모 있다).
  3. CHOOSE의 '이후 혼자 정답률'이 RANDOM보다 낮지 않다(고르는 것이 무작위보다 낫거나 같다). 다섯 몸 가운데 넷 이상에서 만족해야 한다.
  4. ORACLE(정답을 다 받음)과의 차이를 따로 보고한다.
- **4단계 판정 기준(최종 평가 전 고정).** 기준 코어(current)와 NEXT를 비교한다. 다섯 몸 각각에서 세 시드 합으로 본다.
  1. NEXT의 틀림이 기준 코어보다 많지 않다.
  2. 기후실의 해(scorch·ice로 바뀐 칸)가 기준 코어보다 많지 않다.
  3. NEXT의 GOOD 비율이 기준 코어보다 5%p 넘게 떨어지지 않는다. GOOD은 success와 partial이다. part-held와 held는 GOOD이 아니다.
  4. 다섯 몸 합에서 다음 셋 가운데 하나 이상이 기준 코어보다 낫다. GOOD 비율, 틀림 수, 경계가 막은 시도(refused) 수.
     - 수정 기록(최종 평가 전): 처음에는 'GOOD 수'였다. 개발 실행에서 평가되는 명령 수가 학습기마다 달랐다(기후실 523 대 451).
     - 이유: 교사가 과정 중 학습기의 성공과 실패에 따라 가르칠 것을 바꾸기 때문이다. 시드 1에서는 6번째 활동부터 갈렸다. 기준 코어가 틀린 명령을 NEXT가 맞혔다.
     - 그래서 수 대신 비율로 비교한다. 평가된 명령 수도 함께 보고한다.
  5. 질문 수, 실험실 시험 수, 스스로 피한 호출 수(예측된 막힘), 경계가 막은 수를 따로 보고한다. NEXT_nolab(실험실 없음)과 NEXT_noask(질문 없음)도 함께 보고해, 효과가 어디서 오는지 나눈다.
